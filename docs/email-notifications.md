# 中文邮件提醒与每周活动报告

邮件由 ECS 网关发送，使用固定中文模板和 UTF-8 的纯文本 / HTML 双版本，不调用模型生成内容。

## 暂不配置邮箱时

代码已准备好，当前无需注册邮箱、填写授权码或启动发信。保持
`EMAIL_ENABLED=false`（未设置时也默认为 false），邮箱凭据留空即可。
平台可正常运行；停用期间不新增邮件通知、不发送待发邮件，也不运行周报任务。
原有业务记录仍按平台规则保存，但停用期间的即时提醒不会在启用后补发。

现在可以使用下方 `preview` 命令查看示例模板，不会连接 SMTP 或发送邮件。
等邮箱可用时再执行“启用步骤”，将配置项添加到现有 `ecs/.env`，不要用示例文件覆盖已有配置。

## 发信方式

默认选用 **专用 QQ 邮箱 + SMTP SSL（smtp.qq.com:465）**。对于当前的小规模管理员通知，它不需要独立域名或新增邮件平台 SDK，国内管理员也容易配置。使用专用邮箱，不要使用员工私人邮箱作为长期系统身份。SMTP 登录使用邮箱生成的**授权码**，不是 QQ 登录密码。

腾讯的[邮箱连接配置文档](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)列出 QQ 的 SMTP 地址及授权码方式。个人邮箱仍有供应商的发送频率和反垃圾限制；本实现不承诺无限免费发送或送达率。若后续通知量增加，可保留相同实现并切换到阿里云邮件推送的杭州 SMTP 服务 `smtpdm.aliyun.com:465`，但需要完成发信域名 / 地址配置；见[阿里云 SMTP 文档](https://www.alibabacloud.com/help/en/direct-mail/smtp-endpoints)。

## 通知场景

| 场景 | 条件 | 去重 |
| --- | --- | --- |
| 知识冲突 | Worker 上报 `contradiction_alert`，先保存原有冲突记录 | 相同团队及冲突内容，每 UTC 自然日一封 / 收件人 |
| 上传频率异常 | 同一用户最近一分钟已接受的上传超过 5 次 | 每个 UTC 小时最多一封 / 用户 / 收件人；整点前后可能各一封 |
| 可疑上传内容 | 扫描包含指令覆盖、提示词 / 凭据窃取、工具越权或编码执行标记 | 每批上传一封 / 收件人；后续扫描更新仍可在平台查看 |
| 每周用户活动 | 北京时间周一 09:00，统计前一周周一 00:00 至本周周一 00:00（不含结束点） | 每周期一封 / 收件人，重启不重复入队 |

扫描未完成本身不会被称作攻击。邮件提醒要求人工核实，不自动停用账户。保留原来的两种 mock 通知场景，并新增已存在扫描事件的通知；本改动不新增异常检测模型、登录攻击检测或知识冲突检测任务。

收件人为具有有效邮箱的**当前启用管理员**。停用账户、改为 editor、删除账户或更改邮箱后，原地址的待发邮件会跳过。每人独立投递，不暴露其他管理员地址。请在平台账户设置中填写真实可收信邮箱；`admin@localhost` 等初始化占位地址不会投递。

## 周报内容与边界

- 问题数、会话数、不同客户端 IP 数（不作为独立用户人数）。
- 有审计操作的登录用户数、上传数与总大小。
- 用户操作排行（最多 20 人）和操作类型计数。
- 新增知识冲突和源文件扫描警告数（警告包含扫描未完成）。
- 平台管理页面链接。

统计来自知识平台数据库。**不包含 `browser_parse` 的 Grill / 日志分析独立数据库**；这些服务当前没有同一套用户活动审计记录。周报不包含问题原文或 IP 明细。QA 记录仅保留 14 天，停机或保留策略会影响可统计范围。

每次启动/每分钟检查最新已到发送时间的周期；首次启用会补发最近一个完整已到期周报，不回补所有历史周。无活动时仍发送零值周报。

## 启用步骤（在 ECS 上）

1. 准备专用 QQ 邮箱，在邮箱的账户/安全设置中开启 SMTP 并生成授权码。具体菜单以邮箱当前界面为准。
2. 在 `ecs/.env` 填写以下变量，授权码只在服务器上保存，不要发到聊天或提交 Git：

   ```dotenv
   EMAIL_ENABLED=true
   EMAIL_SMTP_HOST=smtp.qq.com
   EMAIL_SMTP_PORT=465
   EMAIL_SMTP_SECURITY=ssl
   EMAIL_SMTP_USERNAME=专用邮箱@qq.com
   EMAIL_SMTP_PASSWORD=邮箱授权码
   EMAIL_FROM=专用邮箱@qq.com
   EMAIL_FROM_NAME=机器人知识平台
   EMAIL_WEEKLY_ENABLED=true
   ```

   `EMAIL_FROM` 应与专用邮箱相同。其他供应商可使用 `ssl` 或 `starttls`；不支持明文登录。
3. 确认 `PUBLIC_BASE_URL` / `ROOT_PATH` 指向正式平台，并确认管理员邮箱。设置 `chmod 600 ecs/.env`。
4. 使用 ECS Python 环境检查配置并查看示例模板（示例命令使用项目开发环境，部署时替换为 ECS 环境）：

   ```sh
   .venv-dev/bin/python -m ecs.app.email_admin check
   .venv-dev/bin/python -m ecs.app.email_admin preview --output /tmp/robot-weekly-email.html
   ```

5. 人工发送测试到一个已启用管理员的邮箱（这个命令会真实发信）：

   ```sh
   .venv-dev/bin/python -m ecs.app.email_admin send-test --to admin@example.com
   ```

   SMTP 接受不代表最终送达；检查收件箱、垃圾邮件及中文显示。
6. 通过现有运维流程重启 ECS 网关以启动后台发送循环。Worker 无需配置邮箱。停用时设置 `EMAIL_ENABLED=false` 并重启 ECS；停用期间不新增通知，也不处理旧待发邮件。

默认 `EMAIL_ENABLED=false`。本次代码实现没有配置真实邮箱、修改线上环境或发送真实邮件。

## 重试与维护

新增 `email_outbox` 表，不删除 `users.email` 或其他业务表。事件按收件人持久化去重；事务领取带有 10 分钟租约，服务中断后可恢复。每分钟最多处理 5 封，每封最多尝试 5 次，临时失败依次等待 1、2、4、8 分钟；明确的永久拒收直接进入 `failed`。更换失效授权码后，仍在重试窗口内的邮件可自动恢复；已耗尽次数的邮件不自动重发。

```sh
.venv-dev/bin/python -m ecs.app.email_admin status
```

状态：`pending`、`sending`、`sent`、`failed`、`skipped`。`sent` 仅表示 SMTP 接受。日志只显示队列编号和错误类别，不打印邮箱授权码、正文或服务器原始错误响应。没有网页邮件管理界面，也没有退信回调。数据库保留队列和正文用于排查，沿用现有数据库备份和访问权限。

SMTP 无法保证跨网络故障的严格恰好一次投递：服务可能在服务器接受邮件之后、更新本地状态之前中断，重试可能产生重复。稳定的 Message-ID 和持久去重减少此风险，但不承诺收件服务一定去重。

验证覆盖中文 MIME、HTML 转义、收件人权限、去重、重启恢复、重试和永久错误、北京时间周界、真实聚合查询以及 Worker 连续消息处理。测试使用临时数据库和模拟 SMTP；启用前仍需要真实邮箱测试。
